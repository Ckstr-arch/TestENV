## Rehearsal checklist

- [ ] Use synthetic demo identities; private password managers and keys stay offscreen.
- [ ] Verify selected fixtures/dates; seeded relative schedules do not advance on restart.
- [ ] Prepare separate browser profiles for student/admin with the exact APP_URL.
- [ ] Show actual CRUD/database changes on disposable data only; avoid cascading team records.
- [ ] Keep DevTools network headers, cookies, tokens and personal SQL fields out of frame.
- [ ] Do not record enrollment keys or recovery codes. Show enabled state and resume recording after entering a factor privately if necessary.
- [ ] Test microphone, captions, readability, transitions and required features.
- [ ] Each speaker explains central code in their own words and references actual PR/commit evidence.
- [ ] Check video, host and repository links from an account with access equivalent to the lecturer’s.

Suggested speaking prompts: A, “Which computed style wins, and why?” B, “What does pending membership allow?” C, “Which server rule prevents this invalid admin write?” D, “How do CSRF and row locks solve different problems?” These are learning questions, not claims of authorship.
