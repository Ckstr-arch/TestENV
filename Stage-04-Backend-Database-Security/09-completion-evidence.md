## Evidence checklist

- [ ] I can trace a native and REST mutation without reading a prepared claim of authorship.
- [ ] I can explain each related table/key and the row state change.
- [ ] I can explain the relevant role/CSRF/ownership boundaries and one failure.
- [ ] I ran and recorded only tests whose environment and destructive scope I verified.
- [ ] I kept personal data, passwords, sessions, keys and recovery codes out of artifacts.
- [ ] My actual patch was reviewed by the domain and backend reviewers.
- [ ] My record distinguishes prior baseline, generated help and my own work.
- [ ] A peer can reproduce my result from the documented safe steps.

If no source change was appropriate, record genuine debugging/test/documentation reasoning and explain its value. Do not invent a cosmetic code change merely to generate a commit count.
